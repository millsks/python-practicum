Strings & Text

Names, messages, files, web pages, data: most of what programs handle is text. This module teaches you to slice, search, clean, and format text with confidence, introduces Python 3.14's new template strings for safe HTML and SQL, and explains how text really becomes bytes through Unicode.

String literals

A string (type str) is an immutable sequence of characters. A sequence is an ordered collection you can index into; you will meet lists and tuples later. You write a string literal between single or double quotes; they are identical, so choose whichever avoids escaping:

a = 'single'
b = "double"
c = "It's easy"            # double quotes let you use an apostrophe
d = 'She said "hi"'
e = """Triple quotes
span several lines."""

Escape sequences

A backslash \ starts an escape sequence, a way to write characters that are hard to type: \n is a newline, \t a tab, \\ a literal backslash, \" a quote, and \N{SNAKE} or \U0001F40D a character by its Unicode name or number.

Raw strings

Prefix a string with r to make it raw: backslashes are kept as-is. That is handy for Windows paths and regular expressions.

Adjacent literals are joined automatically, and + joins (concatenates) strings at runtime; * repeats them: "ab" * 3 is "ababab".

Remember: quotes are interchangeable; \ escapes; r"..." turns escapes off.

Indexing and slicing

Each character in a string has a position called its index. Indexes start at 0, so the first character is s[0]. Negative indexes count from the end: s[-1] is the last character.

A slice s[start:stop:step] extracts a substring. It includes start and excludes stop, which is why s[0:3] has exactly 3 characters. Leave out start to begin at the start and stop to go to the end. A step of 2 takes every second character, and a negative step goes backwards, so s[::-1] reverses a string.

Indexing past the end raises IndexError: string index out of range: "abc"[3] fails because the last index is 2. Slicing, by contrast, quietly clips: "abc"[1:99] is "bc".

Remember: indexes start at 0; slices include the start, exclude the stop; [::-1] reverses.

Immutability and string methods

Strings are immutable: once created, a string never changes. s[0] = "J" raises TypeError: 'str' object does not support item assignment. Every operation that seems to modify a string actually returns a new string. If you want to keep the result, assign it.

Notice that after line 2, name still has its spaces. Only when we rebind name on the last line does it change, and even then the old string object was not modified; the name just points somewhere new.

For case-insensitive comparisons, use casefold() rather than lower(). It handles languages where lowercasing alone is not enough, such as German "ß".

f-strings in depth

An f-string (formatted string literal) starts with f and can contain expressions inside braces { }. Python evaluates each expression and inserts its text:

name, age = "Ada", 36
print(f"{name} is {age} and will be {age + 1} next year.")

The format specification mini-language

After the expression you may add a colon and a format spec, a tiny language that controls how the value is displayed. The general shape is {value:[fill][align][width][,][.precision][type]}:

Older styles: str.format and %

You will see two older ways in existing code. "{} is {}".format(name, age) uses the same format spec language, with positional ({0}) or named ({name}) fields, and is still useful when the template is stored separately from the values, for example TEMPLATE.format(**data). The "%s is %d" % (name, age) style is the oldest; recognize it, but prefer f-strings in new code.

Template strings: t"..." (new in 3.14)

Python 3.14 adds template string literals (PEP 750). They look like f-strings with a t prefix, but they do not produce a string. They produce a string.templatelib.Template object that keeps the literal text and the interpolated values separate, so code can process the values before combining them.

Why: f-strings can be dangerous

Imagine building a web page from a user's comment with an f-string:

comment = "<img src=x onerror=steal(document.cookie)>"
page = f"<p>{comment}</p>"   # the attacker's code now runs in every visitor's browser!

This is called an injection attack: untrusted text (text from a user or another system) is mixed into code (HTML, SQL) and gets interpreted as code. Cross-site scripting (XSS) in HTML and SQL injection in databases are among the most common security bugs in the world. The f-string has already merged everything into one string, so it is too late to tell which parts were trusted.

How template strings work

A Template remembers the pieces. Iterating over it yields, in order, the literal text segments (plain str) and Interpolation objects. Each Interpolation has:

  • .value: the evaluated value
  • .expression: the source text of the expression, such as "name"
  • .conversion: "r", "s", "a", or None
  • .format_spec: the spec after the colon, such as ".2f", or ""

The template also offers .strings (all text segments), .values, and .interpolations as tuples.

A safe HTML renderer

Now we can write a function that escapes only the interpolated values, using html.escape to turn < into &lt; and so on. The literal parts, which the programmer wrote, are trusted and kept as-is. (A function, defined with def, is a named block of reusable code; you will study functions in depth in M05. Here, just read the body.)

The same idea makes SQL safe: a database library can turn each interpolation into a query parameter instead of pasting the text into the query, so t"SELECT * FROM users WHERE name = {name}" can never be hijacked by a name like x' OR '1'='1.

A Template is not a str. str(template) gives its debugging representation, not rendered text. Something, such as your renderer or a library, must process it. That is the whole point: you cannot accidentally use it without deciding how to treat the values.

Why is it important that the renderer escapes the values but not the literal parts? What would happen to the <p> tags if it escaped everything?

Unicode, encodings, and bytes

Computers store numbers, not letters. Unicode is the worldwide standard that gives every character, in every writing system plus emoji, a number called a code point. "A" is 65, "é" is 233, "🐍" is 128013. A Python str is a sequence of code points. ord(ch) gives a character's code point and chr(n) goes the other way.

Encoding: from code points to bytes

Files and networks carry bytes (numbers from 0 to 255), not code points. An encoding is a rule for turning code points into bytes. UTF-8 is the dominant encoding on the web and in modern systems: it uses 1 byte for ASCII characters (plain English letters and digits) and 2 to 4 bytes for others.

  • text.encode("utf-8") turns a str into bytes.
  • data.decode("utf-8") turns bytes back into a str.

A bytes literal looks like b"abc". Bytes are immutable sequences of small integers: indexing b"abc"[0] gives 97.

Garbled text like cafÃ© is called mojibake. It always means bytes were decoded with a different encoding than they were encoded with. The fix is to know, and state, your encoding.

The golden rule of text: decode bytes to str as early as possible (when reading), work with str everywhere inside your program, and encode as late as possible (when writing). Always pass encoding="utf-8" when opening text files; you will practise this in M09.

In Python 3.15 (PEP 686), UTF-8 becomes the default encoding for open() and other text I/O on every platform, including Windows, where the default used to depend on the system locale. Writing encoding="utf-8" explicitly remains good practice, and it works the same in 3.14 and 3.15.

Show solution 
import html
from string.templatelib import Template, Interpolation

def render_html(template: Template) -> str:
    pieces = []
    for part in template:
        if isinstance(part, Interpolation):
            pieces.append(html.escape(format(part.value, part.format_spec)))
        else:
            pieces.append(part)
    return "".join(pieces)

name = "<i>Bob</i>"

Mini-project: a text statistics tool

Mini-projectText statistics

Write textstats.py in your practice workspace. It holds a paragraph of text in a triple-quoted string (or reads one line with input()) and prints a neatly formatted report.

Characters (with spaces):    243
Characters (no spaces):      201
Words:                        43
Unique words:                 35
Longest word:       "statistics" (10)
Average word length:        4.67

Useful tools

  • text.split() for words; len() for counts; text.replace(" ", "") for characters without spaces.
  • Clean punctuation with word.strip(".,;:!?\"'()") and compare with casefold().
  • max(words, key=len) finds the longest word; len(set(words)) counts unique ones (sets come in M06; for now, just use it).
  • Align the report with f-string specs such as {label:<20}{value:>8} and {avg:.2f}.

Acceptance criteria

  • Counts characters with and without spaces, words, and unique words (case-insensitive)
  • Finds the longest word, ignoring surrounding punctuation
  • Reports the average word length to 2 decimals
  • Reports the UTF-8 byte count and it differs from the character count when the text has accents or emoji
  • All numbers line up in a right-aligned column using format specs
  • Runs with pixi run python textstats.py (add a stats task)

Stretch goals

  • Print the five most common words with collections.Counter(words).most_common(5).
  • Render the report as an HTML table using a t-string and your render_html function.
  • Count sentences by counting ., !, and ?.

Quiz

Recap

  • Strings are immutable sequences of Unicode code points; quotes are interchangeable, r"..." is raw.
  • Indexes start at 0; negatives count from the end; slices include start and exclude stop.
  • Methods return new strings: strip, split/join, replace, find, startswith, casefold.
  • f-strings with format specs (:>8.2f, :,, :.1%), = for debugging, and nested specs for runtime widths.
  • Python 3.14 t"..." produces a Template of strings and Interpolations, so values can be escaped or parameterized safely.
  • Encode str to bytes and decode back with an explicit encoding, usually UTF-8.
