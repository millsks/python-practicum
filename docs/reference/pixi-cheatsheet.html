Pixi Cheat Sheet

Every Pixi command and pixi.toml setting this course uses, in one place: installing, adding packages, running code, tasks, environments, lockfiles, global tools, CI, and fixes for common problems. If you know pip, venv, or conda, the translation tables at the end map your habits to Pixi.

  • Install Pixi and create a workspace
  • Add conda-forge and PyPI dependencies, per feature and per platform
  • Define tasks with dependencies, arguments, environment variables, and caching
  • Compose environments from features and test across Python versions
  • Keep the lockfile healthy locally and in CI

The mental model

A workspace is a folder with a pixi.toml manifest (what you want) and a pixi.lock lockfile (exactly what was resolved, for every platform). Environments live in .pixi/envs/<name> and are created from the lockfile. You never activate anything by hand: pixi run puts the right environment on PATH for one command.

flowchart LR
  M["pixi.toml
(what you ask for)"] -- "pixi lock / pixi install" --> L["pixi.lock
(exact versions, all platforms)"]
  L -- "pixi install" --> E[".pixi/envs/default
(installed packages)"]
  E -- "pixi run / pixi shell" --> C["your command"]
  F["features"] --> M

Commit pixi.toml and pixi.lock. Ignore .pixi/. Anyone who clones the repo and runs pixi install gets byte-for-byte the same packages you have.

Add and remove dependencies

Pixi installs conda packages (from conda-forge by default) and PyPI packages in the same environment. Prefer conda-forge: its packages ship compiled libraries and work across languages. Use --pypi only for packages that are not on conda-forge.

CommandEffect
pixi add numpyAdd from conda-forge with a semver range, e.g. numpy = ">=2.3.4,<3"
pixi add "numpy>=2.1,<3" "python=3.14.*"Add with explicit version specs (quote them for the shell)
pixi add --pypi requests-cacheAdd a PyPI package ([pypi-dependencies])
pixi add --pypi --editable --path . my-packageInstall your own src/ package in editable mode
pixi add --pypi --git https://github.com/org/repo.git pkg --branch mainPyPI package from git (also --tag, --rev)
pixi add --feature test pytest pytest-covAdd to a feature instead of the default set
pixi add --platform win-64 pywin32Platform-specific dependency ([target.win-64.dependencies])
pixi add --no-install pandasUpdate manifest and lockfile only
pixi remove numpyRemove (add --pypi / --feature to match how it was added)
pixi search pandasFind a conda package and its latest version
pixi list / pixi tree / pixi tree -i opensslInstalled packages / dependency tree / who depends on openssl
 
[dependencies]                 # conda-forge packages, every environment
python = "3.14.*"
numpy = ">=2.3,<3"

[pypi-dependencies]            # PyPI packages (only when not on conda-forge)
my-app = { path = ".", editable = true }

[target.linux-64.dependencies] # platform-specific
libstdcxx-ng = "*"

Never mix in pip install. Packages installed that way are not in the lockfile, so nobody else gets them, and the next pixi install may remove them.

Tasks

Tasks are named commands in pixi.toml. They run cross-platform (Pixi uses its own shell, so &&, pipes, and $VAR work on Windows too).

[tasks]
fmt  = "ruff format ."
lint = "ruff check ."
test = { cmd = "pytest tests/unit", description = "Fast unit tests" }

# run other tasks first
ci = { depends-on = ["fmt", "lint", "test"] }

# arguments with defaults:  pixi run greet   |   pixi run greet Ada
greet = { cmd = "echo hello {{ name }}", args = [{ arg = "name", default = "world" }] }

# environment variables and working directory
serve = { cmd = "python -m http.server 8000", cwd = "docs", env = { PYTHONUNBUFFERED = "1" } }

# caching: skipped when inputs and outputs are unchanged
build = { cmd = "python -m build", inputs = ["src/**/*.py", "pyproject.toml"], outputs = ["dist/*"] }

# run a dependency in another environment
test-315 = { depends-on = [{ task = "test", environment = "py315" }] }

[feature.docs.tasks]           # tasks that only exist in environments with this feature
docs = "mkdocs serve"
KeyMeaning
cmdCommand string (or list of arguments)
depends-onTasks to run first (names, or tables with task, args, environment)
argsNamed arguments, used as {{ name }} in cmd; optional default
envEnvironment variables for this task
cwdWorking directory, relative to the workspace root
inputs / outputsGlob patterns; when both are unchanged, the task is a cache hit and is skipped
descriptionShown by pixi task list
clean-envRun with a minimal environment
default-environmentEnvironment used when you don't pass -e
 
pixi task list                                   # what can I run?
pixi task add test "pytest tests" --description "All tests"
pixi task alias ci lint test                     # a task that only runs others
pixi task add --feature docs docs "mkdocs serve"
pixi task remove ci
pixi run greet Ada                               # pass a task argument

This repository's own tasks: pixi run serve (the site), pixi run projects, pixi run start p01, pixi run grade p01, and pixi run ci.

Features, environments, and solve groups

A feature is a named bundle of dependencies, tasks, and settings. An environment is a list of features (plus the default feature, which is everything at the top level). A solve group makes several environments share one resolution, so prod and test get identical versions of shared packages.

[dependencies]                  # the default feature: in every environment
numpy = ">=2.3,<3"

[feature.test.dependencies]
pytest = "*"

[feature.lint.dependencies]
ruff = "*"
mypy = "*"

[feature.py314.dependencies]
python = "3.14.*"
[feature.py315.dependencies]
python = "3.15.*"

[environments]
default = { features = ["py314", "test", "lint"], solve-group = "main" }
prod    = { features = ["py314"], solve-group = "main" }        # same numpy as default
py315   = ["py315", "test"]                                       # preview Python
lint    = { features = ["lint"], no-default-feature = true }    # tiny: no numpy
pixi install -e py315           # install one environment
pixi install --all              # install all of them
pixi run -e py315 pytest        # run in one
pixi workspace environment add docs --feature docs
pixi workspace environment list
pixi info                       # environments, features, platforms, cache paths

Specs for the same package from different features are combined, not overridden. Putting python = "3.14.*" at the top level and python = "3.15.*" in a feature makes that environment unsolvable. Put each Python pin in its own feature, as above.

Platforms and system requirements

The lockfile is solved for every platform in platforms, even ones you are not on, so a Mac user's lockfile works on a Linux CI runner.

[workspace]
name = "my-app"
channels = ["conda-forge"]
platforms = ["osx-arm64", "osx-64", "linux-64", "win-64"]

[system-requirements]          # minimum system versions the packages may assume
macos = "13.0"
cuda = "12"

[target.win-64.tasks]          # per-platform tasks (and dependencies, activation)
open-docs = "start docs/index.html"
pixi workspace platform add linux-aarch64
pixi workspace platform remove osx-64
pixi workspace channel add bioconda

Lockfile, update, and upgrade

CommandChanges manifest?Changes lockfile?Use
pixi installNoOnly if the manifest changedCreate/refresh environments
pixi install --lockedNoNo; fails if out of dateCI: prove the lockfile matches the manifest
pixi install --frozenNoNo; installs the lockfile as isReproduce exactly, even if the manifest drifted
pixi lockNoYesRe-solve without installing
pixi update / pixi update numpyNoYes: newest versions within current specsRoutine refresh
pixi update --dry-runNoNoPreview what would change
pixi upgrade / pixi upgrade numpyYes: widens specs to the latestYesCross a major version
pixi reinstallNoOnly if neededRebuild a broken environment

In a merge conflict on pixi.lock, don't hand-edit it: accept either side, then run pixi lock to regenerate it from the merged pixi.toml.

Global tools

pixi global installs command-line tools each into its own isolated environment and puts their executables on your PATH (in ~/.pixi/bin). Use it for tools you want everywhere (gh, git, ripgrep), never for a project's own dependencies.

pixi global install gh ripgrep
pixi global install --environment py python=3.14 ipython   # several packages in one env
pixi global list
pixi global update                # update all global environments
pixi global remove --environment py ipython
pixi global uninstall gh
pixi global edit                  # open ~/.pixi/manifests/pixi-global.toml
pixi global sync                  # make installed tools match that manifest

CI with GitHub Actions

The official prefix-dev/setup-pixi action installs Pixi, installs your environments from the lockfile, and caches them.

name: CI
on:
  push: { branches: ["main"] }
  pull_request: { branches: ["main"] }

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: prefix-dev/setup-pixi@v0.8.1
        with:
          pixi-version: latest
          cache: true                 # cache .pixi keyed on pixi.lock
          environments: default py315 # which environments to install
      - run: pixi run ci
      - run: pixi run -e py315 test

Because the lockfile covers every platform, the same three lines work on Linux, macOS, and Windows. A Python-version matrix is just more Pixi environments, not more setup steps.

Interactive pixi.toml explorer

pixi.toml is plain TOML, so the standard library can read it. Edit the manifest below (add a task, a feature, or an environment) and run the cell to see how Pixi would see it: tasks with their dependencies in execution order, and each environment's resolved feature list.

conda version specs use a single = for "this version, any build" (pandas=3.0.6) and == for an exact match; PyPI specs use ==. Both accept >=, <, and comma-separated ranges.

Configuration and activation

[activation.env]               # set whenever the environment is active
APP_ENV = "dev"
PYTHONWARNINGS = "default"

[pypi-options]
index-url = "https://pypi.org/simple"
no-build-isolation = ["my-legacy-package"]
pixi config list
pixi config set --local tls-root-certs system   # use the OS certificate store (corporate proxies)
pixi config set default-channels '["conda-forge"]'
pixi auth login prefix.dev --token $TOKEN       # private channels

Workspace-local settings live in .pixi/config.toml; user-wide ones in ~/.pixi/config.toml.

pixi: command not foundShell not restarted after installOpen a new terminal, or add ~/.pixi/bin to PATH
