Project 6b: Test Rescue

In every other project, the tests are handed to you and the code is your job. Here it is the reverse. The code already exists and has no tests, and your test suite is what gets graded: it must pass on the real code and catch 28 planted bugs.

⏱ ~4–6 hoursPrerequisites: M46b Testing in Practice
  • Read unfamiliar code and list its hidden dependencies
  • Write characterization tests that pin down what the code actually does
  • Isolate the environment, clock, randomness, network, and filesystem with monkeypatch and tmp_path
  • Test retries and backoff without ever really waiting
  • Assert on standard output, standard error, logs, and exit codes
  • Judge your own suite by the bugs it catches

The scenario

A colleague left and handed you invoicer, a small tool that reads line items, adds tax, converts the currency, and saves an invoice as JSON. It works, as far as anyone knows. It has no tests, and next month the team wants to change how tax is calculated. Nobody is willing to touch it until a test suite can prove that nothing else broke.

Before you read the code in full, open invoices.py and list everything build_invoice depends on that isn't one of its arguments. You should find at least five things. Each one is something your tests have to control.

What the code does

This is the behavior your suite needs to pin down. You must not edit the package, and the grader ignores any edits you make.

ModuleBehavior
config.load_config()Reads INVOICER_CURRENCY (default USD, upper-cased) and INVOICER_TAX (default 0.2). A tax value that isn't a number, or is outside 0 up to but not including 1, raises ValueError.
rates.fetch_rate(currency, retries=3)Reads {"rate": ...} with urllib.request.urlopen. On URLError, it sleeps 1 second, then 2 seconds, then raises RateError after the third failed attempt.
invoices.build_invoice(customer, lines)No lines raises ValueError. Computes net from quantity times cents, then tax. USD uses a rate of 1 and looks nothing up; other currencies call fetch_rate and convert net, tax, and total. The number is INV-YYYYMMDD-NNNN with a random 1000–9999 suffix. Due 30 days after today. A total above 1,000,000 logs a warning. Appends the number to HISTORY.
invoices.is_overdue(invoice)True from the day after the due date onward.
invoices.save_invoice(invoice)Writes JSON under INVOICER_DIR (default invoices), creating the directory. Logs a warning when overwriting. Prints saved PATH.
cli.main(argv=None)Takes one customer argument and reads description,qty,cents lines from stdin, skipping blank lines. Saves the invoice, prints NUMBER total TOTAL CURRENCY, and returns 0. A usage error returns 2 with the message on stderr. A bad line or no lines returns 2 with error: ... on stderr.

Setup and grading

pixi run start p06b     # copies the code to work/p06b_test_rescue/
pixi run grade p06b     # run the grader against your tests

Write your tests in work/p06b_test_rescue/tests/. To run them directly while you work:

cd work/p06b_test_rescue
PYTHONPATH=. pixi run pytest tests -q

The grader copies a pristine package and your tests into a sandbox with network connections blocked, then checks the following:

  • Your suite passes on the original code, in under 20 seconds, with at least 90% coverage.
  • It still passes with INVOICER_* variables already set, with a different real date, and in reverse order.
  • It leaves no files behind.
  • It fails on each of 28 versions of the package that contain one planted bug. When a bug survives, the failure message names the behavior you haven't tested.

Milestones

1. Control the world

  • An autouse fixture clears INVOICER_CURRENCY and INVOICER_TAX
  • The same fixture points INVOICER_DIR at tmp_path
  • It freezes invoices.date, fixes the random suffix, and gives each test a fresh HISTORY

2. The pure-ish parts

  • load_config: defaults, overrides, normalization, and all the bad tax values
  • is_overdue: yesterday, today, and tomorrow
  • parse_line: a valid line

3. The network

  • fetch_rate with a fake urlopen, on success
  • Retries and exact backoff delays, with time.sleep replaced
  • Recovery after one failure, and RateError after the last

4. Invoices and the CLI

  • A full USD invoice, compared as a whole dictionary
  • Conversion to another currency, using a fake rate
  • Warnings through caplog, with the threshold tested on both sides
  • Files and printed messages from save_invoice
  • Every exit code from main, and whether its text went to stdout or stderr

5. Close the gaps

  • pixi run grade p06b passes every check

Hints

Which name do I patch for fetch_rate?

invoices.py uses from invoicer.rates import fetch_rate, so patch invoicer.invoices.fetch_rate. To test fetch_rate itself, patch urllib.request.urlopen instead.

What can stand in for an HTTP response?

The code uses the response as a context manager and passes it to json.load. io.BytesIO(b'{"rate": 0.5}') supports both. The fake must accept the same arguments, so write def fake(url, timeout): ....

How do I record backoff delays?

sleeps = [] and then monkeypatch.setattr(rates.time, "sleep", sleeps.append). That also makes the test instant. Then check sleeps == [1, 2].

How do I freeze date.today()?

You can't patch a method on the built-in type. Define a subclass with a today classmethod and replace invoicer.invoices.date, exactly as in the M46b section on time.

How do I feed stdin to main?

monkeypatch.setattr(sys, "stdin", io.StringIO("pens,2,500\n")).

My order test fails but the normal run passes

Two tests share state. The usual suspects are HISTORY, an invoice file that one test expects another to have written, and os.environ assigned directly rather than through monkeypatch.
